# Отчёт по практике: Мониторинг приложения HabitTracker

## 1. Описание стека
Victoria Metrics (Single Server, развернута через Helm)

## 2. Использованные экспортеры
1. prometheus-net.AspNetCore: библиотека, встроенная непосредственно в приложение. Она автоматически собирает метрики рантайма .NET (использование памяти, HTTP-запросы) и предоставляет выделенный эндпоинт `/metrics` для сбора данных.
2. rometheuscommunity/postgres-exporter: официальный экспортер для PostgreSQL. Развернут как sidecar-контейнер в том же поде, что и основная база данных. Использует общее сетевое пространство пода (`localhost`) для безопасного подключения к СУБД и преобразования её внутренних метрик в формат OpenMetrics.

## 3. Реализованные бизнес-метрики
В приложении реализован статический класс `HabitMetrics`, который отслеживает следующие ключевые показатели доменной области:
1. `habit_created_total` (Counter): Общее количество успешно созданных пользователем привычек.
2. `habit_completed_total` (Counter): Общее количество успешных отметок о выполнении привычки (добавление записи в лог).
3. `habit_deleted_total` (Counter): Общее количество удаленных привычек.
4. `habit_completion_failed_total` (Counter): Количество отклоненных попыток отметить привычку (например, при превышении дневного лимита, попытке отметить привычку дважды за один день или при конкурентной ошибке уникальности).

## 4. Настройка Service Discovery
Сбор метрик настроен автоматически без жесткого прописывания IP-адресов. В манифестах `Deployment` для приложения и для PostgreSQL добавлены стандартные аннотации, которые Victoria Metrics использует для автоматического обнаружения таргетов:
```yaml
annotations:
  prometheus.io/scrape: "true"
  prometheus.io/port: "8080" # для API (или "9187" для postgres-exporter)
  prometheus.io/path: "/metrics"
