## 1. Использованные абстракции Kubernetes

| Абстракция | Объект | Назначение |
|---|---|---|
| Pod | `postgres`, `migrate`, `api`, `web` | Контейнер + сеть + том; при пересоздании меняет имя и IP |
| Deployment | `postgres`, `api`, `web` | «Держи N подов»: самовосстановление и масштабирование |
| Service (ClusterIP) | `api`, `postgres` | Внутренний DNS-адрес и балансировка по подам |
| Service (NodePort) | `web` (30080) | Доступ к UI с хоста |
| Endpoints | у всех сервисов | Список IP подходящих подов, обновляется автоматически |
| Labels + Selector | `app=postgres/api/web` | Как Service находит свои поды |
| Secret | `secret` | Пароли и строка подключения (`secretKeyRef`), в git не хранится |
| PVC / PV | `postgres-pvc` (1Gi) | Диск PostgreSQL, переживает пересоздание пода |
| Job | `migrate` | Разовые миграции БД: `restartPolicy: Never`, `backoffLimit: 3` |
| CoreDNS | — | Имя Service → IP (`api` → ClusterIP) |
| imagePullPolicy: Never | `02`, `03`, `04` | Образы собраны локально, загружены через `minikube image load` |

## 2. Взаимодействие сервисов

```
Браузер → http://127.0.0.1:xxxxx (minikube service web --url | kubectl port-forward)
   ↓
Service web (NodePort 30080) ── selector: app=web
   ↓
Pod web (nginx):  / → статика React
                  /api/* → proxy_pass http://api:8080
   ↓
Service api (ClusterIP :8080) ── selector: app=api   ← балансировка по репликам
   ↓
Pod api ×N (Kestrel), строка подключения берётся из Secret (Host=postgres)
   ↓
Service postgres (ClusterIP :5432) ── selector: app=postgres
   ↓
Pod postgres + PVC (данные переживают пересоздание пода)
```

- Обращения идут **по имени Service, а не по IP**: поды пересоздаются с новыми адресами, Service сам переписывает `Endpoints`.
- **Selector + Labels** — единственный механизм поиска подов (`selector: {app: api}` → поды с `app=api`).
- Frontend ходит на **относительный путь** `/api`, nginx проксирует внутрь кластера
